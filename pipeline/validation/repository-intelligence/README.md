## 兼容性与复现

`compatibility.json` 保存数据库副本的逐表 hash：18 个 Spec、9 个执行状态、101 个事件、30 个仓库及 161 条仓库历史均未被评分更新。生产数据库只以 SQLite mode=ro 打开做 backup；新评分记录在隔离副本的 source_observations 中追加。无新表、user_version 保持 2。旧 V1 的复制迁移和旧 Spec 兼容同时由原回归覆盖。

`reproducibility.json` 保存相同快照、固定策略和固定评估时刻重复运行得到的字节级相同结果。`replay.py` 可直接重新生成固定历史报告，不依赖被 gitignore 排除的运行资料。历史回放不是当前 GitHub 状态核验。

## 已知边界

- 本轮没有在线 API 冒烟测试；401/403/429、预算、分页和 GET-only 使用受控接口测试。
- 实质 Commit 是保守代理指标；大仓库超过详情预算会显示 unknown，不推断缺乏维护。
- 政策、受众与技术价值的语义结论仍需审阅和带来源的结构化事实。程序约束证据格式、时效、门槛与公式，不证明人工陈述真实。
- TTL 缓存是有限时效观察，metadata/HEAD 未变不保证所有 PR 讨论未变；Contributor 发布前仍完整重新检查。
- 旧 60 天数据不能补算 90/180 天覆盖；下一轮需要按预算补采。
- 没有自动 Push、PR、评论、邮件或定时任务；实际发布仍需集中审批。
